# Vercel deployment notes

This project is a React/Vite frontend served by an Express backend from the same origin.

## What was changed

- `server.ts` now exports the Express app as the default export, which lets Vercel detect the Express server.
- Local development still uses Vite middleware.
- Production assets are built into `public/`, which Vercel serves as static assets.
- `/api/*` remains handled by Express, so existing frontend calls such as `/api/students` and `/api/drives` do not need a new base URL.
- The server listens on `process.env.PORT` locally and lets Vercel manage the function listener in deployment.
- `vercel.json` runs the Vite production build without overriding the Express function routing.
- Node is pinned to 24.x for Vercel.

## Important data note

The current `server/db.ts` uses in-memory Maps. This means drive, registration, round, and placement data can be lost when a server instance is recycled or when requests reach different instances. A real persistent database is required for production data durability.

The current Google Form URLs are also mock URLs generated by `server/db.ts`. Creating real Google Forms/Sheets requires Google API credentials and an OAuth/service-account integration; this deployment fix does not fabricate real Google API credentials.
